# ContentLab audit and Focus Queue upgrade

Baseline: `151f1e2` on `main`. Scope: frontend content workflow, session lifecycle, browser caching, bundle composition, dependency advisories, and repeatable validation. Production database policies and live deployment were not changed or independently verified.

## Findings and changes

| Priority | Finding | Resolution |
| --- | --- | --- |
| P1 | `loginUser` accepted emergency admin aliases without password verification when an environment flag was disabled. The documented Auth/RLS cutover was already complete. | Removed the emergency login path. Supabase Auth is now mandatory regardless of the retired cutover flag. |
| P1 | A persistent workspace snapshot contained tasks, comments, documents and notifications without a user boundary. Logout did not clear workspace state. | Retired persistent workspace caching, purge the old key, keep only a session memory snapshot and clear it on identity changes. A fresh page load fetches authorized data again. |
| P1 | In-flight reads and failed optimistic writes could restore the previous account's data after an account switch. | Session generation guards protect data setters and refresh responses. A refresh sequence also rejects superseded reads. Auth profile callbacks ignore superseded events and unsubscriptions. |
| P2 | UTC date slicing classified deadlines using yesterday during the first seven hours of the day in Jakarta. | Local calendar dates, refresh on focus/across midnight, and calendar-day arithmetic independent of DST. Shared by overview, overdue filter and Focus Queue. |
| P2 | Broad `id.includes('react')` chunking pulled editor dependencies into the initial React vendor bundle. | Match actual `react`, `react-dom`, and `scheduler` package paths. Rich-text editor code stays in its lazy chunk. Removed ineffective dynamic service imports. |
| P2 | No automated regression suite or CI gate. | Added unit, interaction, session regression and desktop/mobile browser tests plus GitHub Actions. |
| P2 | `.env` was tracked and not ignored. | Removed it from the Git index, retained the local file and added ignore rules. Existing Git history is unchanged. |
| P2 | Development dependencies included advisory-affected nanoid and postcss versions. | Updated compatible transitive versions using npm audit fix; audit reports zero known vulnerabilities at validation time. |
| P3 | 17 lint warnings and template README content. | Clean lint output and documentation of actual workflows. |

## Product upgrade: Focus Queue

The dashboard now starts with a ranked action list within the existing personal/studio and client/brand scope. It prioritizes overdue tasks, today's deadlines, reviews, urgent tasks, and upcoming work. Published/Done tasks are excluded; Scheduled items remain active. Each row explains why it matters, displays checklist progress, and opens the existing task editor.

Filters cover all active work, overdue, due today, in review, and unplanned. Search covers title, client, brand, assignee and channel. The first five rows keep the overview compact, with explicit expansion, empty states, keyboard activation and reduced-motion support. Priority rules are deterministic, with no AI service or external data transfer.

## Validation

- `npm run lint`: zero warnings.
- `TZ=Asia/Jakarta npm test`: 16 regression tests covering priorities, invalid dates/checklists, local midnight, search, pagination, keyboard actions, cache behavior, removed login bypass, late refreshes, sign-out and failed writes crossing account boundaries.
- `npm run build`: TypeScript and production build pass, without the previous chunk warnings.
- `npm run test:browser`: desktop (1440px) and mobile (375px) synthetic dashboard fixture; checks filtering, keyboard task opening, empty states, horizontal overflow, reduced motion and console errors. No production data or credentials are used.
- `npm audit`: zero known vulnerabilities after compatible updates.
- React vendor chunk: 507.85 KB → 189.64 KB raw; 157.53 KB → 59.65 KB gzip. This measures one initial vendor chunk, not end-user page-load time or total application size.

## Remaining boundaries

- Live Supabase RLS, storage policies, account provisioning and the production deployment still require a separately authenticated operational verification. The SQL cutover runbook records the prior migration; this audit does not reapply it.
- Legacy Apps Script integrations and database migration tools remain for compatibility. They are not a login fallback.
- The application still has a large root state component and full-workspace realtime refreshes. More granular server queries and mutation conflict handling would be a separate architectural change.
- Removing `.env` from tracking does not remove previous commits. Public Supabase anon keys still require correctly enforced RLS and are not server secrets.
